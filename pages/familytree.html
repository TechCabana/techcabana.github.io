About This Project

Purpose & Motivation

A family tree is usually either a static chart someone drew once, or a paid product that wants an account before it shows you anything. I wanted something in between: a canvas you could actually edit — add a member, draw a relationship, drag things around — that stayed entirely on the machine you opened it on.

Nothing about it needed to be shared or synced. It needed to open, remember what you put in it last time, and get out of the way.

The Constraint That Shaped Everything

No accounts, no cloud saves, no server the data ever passes through. That single decision is why the tree lives entirely in the browser's localStorage, under one key (familyTreeData), read back on load and rewritten on every edit. There is nothing to sign into and nothing to lose access to — but also nothing to fall back on if that one browser's storage is ever cleared, which is the trade-off a self-contained tool makes.

Implementation & Technical Considerations

Adding, editing and deleting members and relationships all mutate one in-memory object, which is deep-cloned from the seed data on first load and then persisted to localStorage after every change. Filtering runs across seven dimensions at once — tag, side, generation, role, relationship link, status, and a toggle for deceased members — so the tree can be narrowed to, say, one side of the family at a generation, without touching the underlying data.

The connection lines between cards are SVG, redrawn by reading each card's getBoundingClientRect() after every layout change. Read those coordinates the instant the DOM updates and they come back stale — the browser hasn't finished laying the cards out yet, so lines snap to the wrong position. The fix is a short setTimeout before redrawing: 50ms after a filter changes, 300ms after a member is added or removed, long enough for layout to actually settle first.

Testing & Reliability

There is no automated test suite — this is a personal tool with one user testing it by using it. The import path is the one place that gets a runtime check regardless: an imported JSON file is only accepted if it has both a members and a connections array, so a malformed file fails loudly rather than silently half-loading.

Decisions Worth Explaining
Decision Why
Save to localStorage, not a backend No accounts and no server ever seeing the data was the point. A database and an API would have solved a problem this tool doesn't have.
Redraw connection lines on a short delay, not immediately Reading card positions before the browser finishes layout returns stale coordinates, so lines snap to the wrong place. Waiting one paint cycle first fixes it.
Five export formats, not just JSON The tree gets looked at as much as it gets edited. PNG, PDF and SVG are for printing or sharing it; CSV is for pulling the raw data into a spreadsheet. Only JSON round-trips back in.

Design Approach

The canvas follows the same dark, tokenised system as the rest of the site — flat surfaces, hairline borders, one accent colour reserved for interaction. Tags carry colour because that colour is the only thing distinguishing them at a glance across dozens of cards; everything else on a card is text.
