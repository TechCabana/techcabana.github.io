About This Project

Purpose & Motivation

I wanted to learn new words without remembering to check a website or install another app. The fix: a Python script that fetches the word of the day from Wordnik and texts it to my phone via Twilio. Set up once, it runs in the background with no daily effort.

The Constraint That Shaped Everything

Twilio charges per message past its free trial and caps a single SMS at 1,600 characters — a limit the script's own formatting comment names directly. Both facts push the same way: the message has to fit, and it has to actually send, every single day, with nobody watching it run.

That is why the definition is never touched but the example gets truncated first when a message runs long, and why a total failure to fetch the word still sends an SMS — just one that says so, rather than staying silent.

Implementation & Technical Considerations

The fetch, format and send steps are three plain functions, each wrapped in its own try/except. The fetch step separates a timeout from a general request failure from an unexpected error, and logs each one under a different message — so word_of_day.log says which of the three happened, not just that something went wrong. Task Scheduler runs this with nobody watching the terminal, so the log file is the only record of whether today's message went out at all.

Message construction cleans stray <i>/<b> tags out of the API response before building the SMS, then checks the assembled length against the 1,600-character cap with headroom to spare: past 1,500 characters, the example is trimmed to fit and the definition is left untouched.

Testing & Reliability

There is no automated test suite; a script that runs once a day is verified by watching it run and reading the log it leaves behind. Reliability comes from the failure path rather than from tests: if the word can't be fetched at all, the script still calls send_sms() with an error message instead of exiting quietly, so a broken morning looks like a text saying so — not like nothing arriving and no way to tell why.

Decisions Worth Explaining
Decision Why
Log every run to a file, not just the console Task Scheduler runs this headless. word_of_day.log is the only way to know, after the fact, whether today's message went out.
Send an SMS on failure instead of failing silently A daily text that quietly stops is indistinguishable from nothing happening. A failure text is what actually gets noticed and checked.
Truncate the example, never the definition The definition is the part that teaches the word. The example is illustrative and can lose its ending gracefully; the definition can't.
Task Scheduler, not a hosted job An always-on server for one SMS a day would cost more than the SMS itself. Task Scheduler already ships with Windows.
