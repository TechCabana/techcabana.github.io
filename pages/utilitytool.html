About This Project

Purpose & Motivation

I kept needing to batch-compress a folder of photos or rename a pile of files, and the options were paid services or tools that didn't quite fit. So I built a cross-platform desktop app that handles both image and file work in one place, organised into tabs so switching between them doesn't lose your place.

The Constraint That Shaped Everything

It had to run on someone else's machine with no Python installed, and it had to stay responsive while it worked through hundreds of files. Both come from the same decision: build with PyInstaller's --onefile --windowed mode into a standalone .exe or .app, and run every batch job on a QThread rather than the main thread — a window that freezes mid-batch looks broken even when it isn't.

Application Interface

Modern dark-themed interface with sidebar navigation

Implementation & Technical Considerations

Image tools compress, resize — including two named passport presets (India and Netherlands, both 35×45mm) — and convert between five output formats (original, JPEG, PNG, WEBP, TIFF). File tools batch-rename with a custom pattern, prefix, suffix, zero-padded auto-numbering, regex find-and-replace, and date-based naming from either the current date or a file's own modified time. Both tabs hand their batch off to a QThread before starting, so a run of a few hundred files reports live progress instead of freezing the window until it's done.

Presets and settings are written to whichever directory each OS actually expects: Library/Application Support on Mac, %APPDATA% on Windows, ~/.config on Linux — one function picks the right one so settings survive an app update rather than living next to a binary that gets replaced.

Testing & Reliability

There is no automated test suite. Reliability here comes from keeping the heavy work off the UI thread and giving batch jobs a visible progress bar and a stop control, rather than from a suite of assertions — a desktop tool with one user is verified by running it against a real folder of files.

Decisions Worth Explaining
Decision Why
Run batch jobs on a QThread, not the main thread Pillow processing hundreds of images blocks whatever thread it runs on. Without this the window would freeze and look hung during a real batch.
Store presets in each OS's own app-data folder Library/Application Support, %APPDATA% and ~/.config are where each platform expects settings to live and survive an update — not a file sitting next to the executable.
Ship a PyInstaller onefile build, not a pip package The point was to hand someone a .exe or .app that runs with no Python installed, not to publish a library someone else has to set up.
Two dependencies, not an imaging framework PySide6 for the UI and Pillow for image work cover everything the tool needs. Anything more is another version to pin and rebuild for.

Design Approach

The interface follows the same dark, tokenised system as the rest of the site: flat surfaces, hairline borders between panels, and progress feedback that reports state rather than decorating the window while it works.
